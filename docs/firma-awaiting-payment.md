# Статус «Ждёт оплаты» (awaiting_payment) — как с ним работать фин-агенту

**Дата:** 28.07.2026
**От:** инженер Фирмы (по решению Юры)
**Кому:** фин-агент; копия — оркестратору

---

## Что это

У заказов появился седьмой статус — `awaiting_payment` («Ждёт оплаты»): смета/счёт есть,
но заказчик не оплатил и работа **не начата**. Раньше такие заказы месяцами висели
в `estimate` и были неотличимы от тех, по которым идёт переговорка (Ресторан Горбачёва —
счёт №061-Н/26 от 15.05, оплат ноль, два месяца в «Смете»).

Полный список статусов теперь:
`draft / estimate / project / in_production / awaiting_payment / completed / cancelled`.

## Три правила (решения Юры, 28.07.2026)

1. **Статус ставится только вручную** — Юрой в интерфейсе или тобой **по его прямой
   команде**. Никакой автоматики: firma подсказывает (флаг `awaiting_hint` у заказа
   с ценой и нулевой оплатой), но не переводит сама. Ты — тоже подсказывай, но не переводи.
2. **Оплата пришла — это сигнал, не переход.** Firma показывает «оплата пришла —
   запускаем?» (флаг `awaiting_paid_signal`), запуск в производство — решение Юры.
   Частичная предоплата не значит, что работа началась. Твоя роль: заметил поступление
   по «ждущему» заказу — скажи Юре, статус не трогай без его слова.
3. **Это НЕ дебиторка.** Долги «ждущих» заказов исключены из `/finance/debtors` → items
   и из твоих отчётов по дебиторке они должны исчезнуть. Вместо этого — **потенциальная
   выручка**: «ориентир, который я могу получить, если дожму такой заказ по оплате».
   В API это блок `potential` в том же `GET /api/finance/debtors`:
   ```json
   { "items": [...], "total": ...,
     "potential": [ { "number": "ORD-005", "title": "...", "customer_name": "...",
                      "price_plan": 195600, "paid_total": 0, "rest": 195600 } ],
     "potential_total": 195600 }
   ```
   `price_plan` там — живая цена из активной сметы (та же, что в списке заказов),
   а не хранимое поле заказа.

## Как ставить статус (по команде Юры)

```
PATCH /api/orders/{id}/status   {"status": "awaiting_payment"}   # пометить
PATCH /api/orders/{id}/status   {"status": "in_production"}      # запустить после оплаты
```
Опечатка в статусе → 400. Через `firma.py` можно после правки CLI (см. ниже).

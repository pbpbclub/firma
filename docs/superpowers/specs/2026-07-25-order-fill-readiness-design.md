# Готовность к заполнению заказов (25.07.2026)

Дизайн-документ брейншторма. Задача: Юра переходит к заполнению актуальных заказов
и спрашивает, всё ли готово и правильно ли считается себестоимость.

## Что выяснилось на живых данных

| Факт | Цифра |
|---|---|
| Заказов (не в архиве) | 15: MeRA 9, Транзит 3, pbpb 2, без бренда 1 |
| Смет | 19: 14 черновиков, 4 согласованных, 1 заменённая |
| Себестоимость-заглушка (`цена ÷ наценка 2.0`, состава нет) | 10 позиций |
| Суммы без состава, введённые осознанно (Транзит 87%, доставка) | 9 позиций |
| Позиций с реальным составом | 25 |
| Виды работ без ставки | 10 из 15 |
| Выученные цены (`price_book`) / правила сопоставления | 0 / 0 |
| Строки рецептур каталога с привязкой к номенклатуре | 0 из 194 |
| Живые прайсы металла | 5 467 позиций, нержавейки 409, обновлены 20–25.07 |

**Корень проблемы.** `production.py estimate-create` пишет себестоимость как
`цена ÷ наценка` — это документированная «черновая заглушка». Но `cost-check` задаёт
вопрос по позиции только при `cost_total <= 0`, а заглушка не ноль. Поэтому проверка
показывала «вопросов: 0» на сметах, за цифрами которых ничего не стоит.

## Решения (согласованы с Юрой)

1. Актуальная смета при дублях — **последняя по дате**.
2. По 10 заглушкам Юра называет **верные суммы одной цифрой**, без разбора на состав.
3. Себестоимость MeRA собирать **из типовых узлов** (нержавейка ₽/м², гибка, сварка,
   монтаж) — изделия уникальны, но узлы повторяются.
4. Порядок: **сначала инструменты, потом ввод данных**.

## Этап 1 — реализовано

**Бэк**
- `_is_stub_cost` (`costing.py`): заглушка = позиция без строк, наценка ровно 2.0,
  `cost × markup == sale`. Осознанные суммы (произвольная наценка) выделены отдельно
  через `_is_sum_without_breakdown` — они не тревожны.
- `cost-check` перестал молчать: заглушка попадает в `missing` с `kind="stub"` и
  вопросом «себестоимость N ₽ — это просто цена ÷ наценка, а не расчёт. Сколько она
  стоит на самом деле?». Вопрос видят и веб, и `firma.py cost-check` у фин-агента.
- `GET /estimates/readiness` — сводка: дубли смет, заглушки, суммы без состава,
  виды работ без ставки, подозрительные ставки (per_unit ≥ 10 000 ₽, source=history).
- `POST /estimates/sets/{id}/keep-actual` — оставить смету актуальной, остальные
  пометить заменёнными. Раньше `superseded` ставился только автоматически при approve.

**Фронт** — вкладка «Готовность» в разделе «Заказы» (`components/order/ReadinessPanel.tsx`):
счётчики, дубли смет с кнопкой «оставить эту», построчный ввод реальной себестоимости
(Enter сохраняет), список подозрительных ставок, быстрый ввод ставок по видам работ.

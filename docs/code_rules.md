# Правила кода (пополняется ночным review_lite)

Выведены из реальных находок ревью. Читать перед правкой кода.

## 2026-07-17
- В списочных эндпоинтах не делать запрос к БД на каждую строку результата (N+1): агрегаты/связанные данные грузить пакетно одним запросом или JOIN-ом. _(источник: backend/routers/orders.py:75; backend/routers/orders.py:377)_
- Если функция уже принимает опциональный параметр загруженной сущности (например est=), переиспользовать его во всех внутренних вызовах, а не запрашивать одно и то же из БД повторно в рамках одного обработчика. _(источник: backend/routers/orders.py:75; backend/routers/orders.py:377)_

## 2026-07-20
- Производные денежные итоги (выплачено/факт) должны применять тот же инвариант «одна оплата = один факт», что и остальной код: не складывать creditors.paid и expenses.amount без исключения связанных (creditor_id / совпадение tx_id) записей — иначе покрытый платёж задваивается. _(источник: backend/routers/masters.py:300; backend/routers/masters.py:152; backend/db.py:40)_
- На fallback-ветке переоткрытия соединения с БД закрывать предыдущий handle перед повторным connect, чтобы не текли соединения при частичном сбое (connect прошёл, первый запрос упал). _(источник: backend/routers/masters.py:300; backend/routers/masters.py:152; backend/db.py:40)_

## 2026-07-21
- Признак «уже обработано/разнесено» нельзя строить на запросах, обёрнутых в `except Exception: pass`: при отсутствии таблицы, колонки или файла БД сущность молча станет «необработанной» и будет проведена повторно — такие сбои обязаны падать или логироваться с алертом. _(источник: backend/routers/payments.py:28; backend/routers/payments.py:95; backend/routers/payments.py:80)_
- Если выборка ограничена LIMIT, а часть строк отсеивается уже в Python, «запас» вида `limit * N` — молчаливая потеря данных: фильтровать в SQL либо возвращать явный признак усечения/курсор. _(источник: backend/routers/payments.py:28; backend/routers/payments.py:95; backend/routers/payments.py:80)_
- Новая запись сущности, для которой уже есть эндпоинт с валидацией и побочными эффектами (платёж, расход), должна создаваться через общую функцию этого эндпоинта, а не прямым INSERT в таблицу. _(источник: backend/routers/payments.py:28; backend/routers/payments.py:95; backend/routers/payments.py:80)_

## 2026-07-22
- PATCH обязан уметь очищать поле. Отсев `None` из `model_dump()` смешивает «поле не прислали» и «прислали null для очистки»: очистка молча теряется, ответ 200, значение старое. Использовать `model_dump(exclude_unset=True)`; пустые строки необязательных полей приводить к `NULL`. _(источник: backend/routers/suppliers.py:82)_
- Форматтеры не путают `0` и «нет значения». `if (!n) return "—"` прячет реальный ноль (закрытый долг, нулевой расход) как отсутствие данных. Проверять на `null`/`undefined`/`NaN`, не на falsy. _(источник: frontend/src/pages/wiki/helpers.ts:15; frontend/src/components/ui/priceMath.ts:17)_
- Подсказки/производные, зависящие от суммы по заказу, считать от фактического итога (SELECT SUM в той же транзакции после вставки), а не от нуля «потому что это первый платёж в обработчике». _(источник: backend/routers/orders.py:739; backend/routers/payments.py:182)_

## 2026-07-22
- Колонка, добавляемая ALTER-миграцией, обязана быть и в CREATE TABLE ленивой инициализации схемы (`_ensure_tables`/bootstrap), а сама миграция — быть no-op при отсутствующей таблице: иначе на чистой БД порядок «создали старую схему → INSERT новых колонок» падает, а стартовый ALTER роняет приложение. _(источник: backend/routers/catalog.py:11; backend/db.py:640; backend/routers/costing.py:60)_
- Резолв цены/справочника из внешней БД нельзя глушить `except Exception: pass`: недоступность прайсов должна отличаться от «позиция не найдена», иначе в себестоимость молча уходит 0 или лишний вопрос вместо явной ошибки/деградации. _(источник: backend/routers/catalog.py:11; backend/db.py:640; backend/routers/costing.py:60)_
- Если у ставки/цены есть схема начисления (fixed / per_unit / hourly / percent), схема обязана определять участие qty в формуле — единый `unit_price = rate` для всех схем тихо умножает фиксированную стоимость на количество. _(источник: backend/routers/catalog.py:11; backend/db.py:640; backend/routers/costing.py:60)_

## 2026-07-23
- Новый флаг/поле в единой точке записи (upsert) обязан иметь семантику «не передан → сохранить текущее значение»: параметр с дефолтом в ветке UPDATE молча затирает значение у всех вызывающих, которые о нём не знают. Использовать sentinel (None) и не включать поле в SET, если оно не задано. _(источник: backend/routers/rates.py:80; backend/routers/catalog.py:283; backend/routers/estimates.py:52)_
- Если у сущности есть «якорное» поле, введённое человеком (ручная цена), а рядом хранится производное от него (наценка, %), то полнотельный PUT обязан либо принимать якорь от клиента, либо восстанавливать его из существующей записи — иначе пересчёт от округлённого производного тихо меняет якорь при каждом сохранении. _(источник: backend/routers/rates.py:80; backend/routers/catalog.py:283; backend/routers/estimates.py:52)_

## 2026-07-24
- Операция, копирующая или разбивающая строку сущности, у которой есть производные движения по внешнему ключу (fund_transactions.expense_id, привязки контрагентов), обязана пересоздать эти движения и связи для КАЖДОЙ новой строки, а не только скопировать флаг-признак (payment_source): иначе движение остаётся одно на исходной строке и позднейшее удаление/правка части рассинхронит связанный контур. _(источник: backend/routers/orders.py:1091; backend/routers/orders.py:1088; backend/routers/finance.py:212)_

## 2026-07-25
- Обязательное поле в Pydantic-модели тела, которое обработчик не читает, — ловушка: обработчик берёт значение из пути/другого источника, а клиент шлёт пустое тело и получает 422. Поле, не используемое обработчиком, делать Optional или убирать; сверять поля модели тела с тем, что реально читается в теле и что отправляет фронт. _(источник: backend/routers/costing.py:495; backend/routers/costing.py:285; backend/routers/catalog.py:332)_
- Новый эндпоинт, использующий модуль/символ (datetime.utcnow, json и т.п.), обязан сам импортировать его в своём модуле, а не полагаться на импорт соседнего кода; для меток времени в SQLite предпочитать единый способ по файлу (datetime('now') в SQL либо Python-datetime), а не смешивать. _(источник: backend/routers/costing.py:495; backend/routers/costing.py:285; backend/routers/catalog.py:332)_
